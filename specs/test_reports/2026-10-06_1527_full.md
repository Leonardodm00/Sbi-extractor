## Problems in the spec
- Every block entry is `Confirmed: inferred` (drafted from the code), apart from the three points the author confirmed on 2026-10-06. Agreement between the code and those entries is not independent evidence. All Block 1-5 oracles above other than the confirmed ones fall under this.
- The Block 4 oracle "With label_spec = None ... A9 is the only assertion in assertions_passed" contradicts the A7 entry of the same block, which applies whenever l2_normalize is set. The code passes A7 as well (F11). One of them needs correcting.
- K = floor(T / Delta_t): the spec does not say whether the floor is taken of the exact or the floating-point ratio. For T = 0.3 s and Delta_t = 0.1 s, the computed ratio is 2.9999999999999996, giving K = 2, where exact arithmetic gives 3. The code takes the computed ratio. It is harmless for the T and Delta_t values used, but the confirmed rule 1 shows the author wants rounding robustness elsewhere.
- Rule 1 must "hold where theta is written (the simulator) and where it is read back". The simulator (Astro-Neuron-Network HPC_main_sweep.py:416) also uses the non-robust `>= 1.0`, so fixing F1 here alone makes load_registry's cross-check fail for any boundary axis.
- A4 is defined per shard, which makes every single-row shard invalid (F9). The spec does not say whether that is intended.
- The spec says nothing about all-zero (silent) traces, which map to z = 0 and violate A7 (F10). It should say whether such a record is an error, is skipped and counted, or is exported.
- Missing job_args.json or missing keys: the spec gives defaults for conn_prob bounds and kernel bounds, but not for simtime. Its silence was read as "no default allowed" (F2), following section 4.
- det_ch's range is marked (inferred) in section 3. The behaviour for out-of-range indices is not stated; it was read as "raise", following section 4 (F3).
- Q4 (batch-size invariance) is still open. Differences of about 1e-7 were measured between batch sizes, inside the 1e-6 the spec allows.
- No specs/DECISIONS.md exists (Q5). The decisions in section 4 could not be checked against a log.
