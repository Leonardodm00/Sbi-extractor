### Block 9 (the cohort map)

- M1. The map is read with the csv module. It has a header row, and the four
  required columns may come in any order. Extra columns are ignored,
  including quoted commas and quoted newlines inside them.
- M2. Each row is matched on the manifest's out_dir with os.sep replaced by
  "/".
- M3. donor and rep_group are stripped of surrounding blanks. A label left
  empty is refused, for an excluded well too.
- M4. include is one of yes, no, true, false, 1, 0, case-insensitive. Any
  other value is refused, including "" and " yes" (only the two labels are
  stripped).
- M5. A donor id is the label's position in sorted(set(donor labels of the
  INCLUDED wells)), in Python string order ("10" < "9" < "B" < "a").
  rep_group ids follow the same rule. Labels of excluded wells take no id.
- M6. An excluded well gives no row, and its archives are not read. Batch
  ranks still cover every manifest well.
- M7. Each of these refusals raises CohortMapError, is printed as REFUSED,
  and writes no shard. On the map side:
  - a required column missing, or named twice;
  - an out_dir naming no well of the manifest;
  - a well with no row, or with two rows;
  - an empty label;
  - an include value outside the set;
  - every well excluded;
  - a non-ASCII file, a UTF-8 BOM included;
  - a row whose field count differs from the header's (the message names the
    line and both counts);
  - a line the csv module cannot parse;
  - a missing file.

  On the manifest side:
  - a manifest without wells;
  - a well without out_dir;
  - an out_dir listed twice.
- M8. The sidecar's latent_spec, which is inside the contract digest, gains
  "cohort_map". It is null without a map. With a map it holds:
  - "sha256": the map file's sha256;
  - "donor_labels" and "rep_group_labels" (list index = id);
  - "excluded": the excluded out_dirs;
  - "n_wells_included".

  per_class and n_wells count included wells only, and the map changes the
  contract digest.
- M9. The printed lines, before the per-class lines:
  `[real] cohort map <path> sha256 <16 hex>: <k> of <n> wells excluded; <D>
  donors; <G> pairing groups`, then one `[real]   excluded <out_dir>` line per
  excluded well. Without a map: `[real] cohort map: none (donor = rep_group =
  well)`.
- M10. The shard passes stage-1 `check_arrays` with rep_group, and
  `concat_shards` reads it back. With a latent_bank older than SBI 88c32e5,
  bank_real refuses and names the commit.
- M11. Two runs give identical arrays and an identical digest.

### Block 10 (partial topologies)

- P1. K(t) = `_resolved_n_workers` x `n_params_per_worker` from the raw
  task's job_args.json. Each must be a JSON integer >= 1. A missing key, 0,
  -1, 4.0, "4", true, null or NaN is refused, naming the task and the key.
  Cross-check (general reasoning, from reading the ANN source at fe7152c,
  `HPC_main_sweep.py:1743`): sims_per_topo = n_workers x n_params_per_worker.
  A discarded run writes one `_failures.jsonl` line and no `iter_<i>.json`
  (`:673-682`), so f counts each dispatched run once.
- P2. f(t, k) = the number of `iter_<i>.json` files plus the number of
  non-blank lines of `_failures.jsonl` (0 without the file). Blank and
  whitespace-only lines, CRLF, decoy names and a folder named like a sidecar
  do not count.
- P3. A topology is partial iff f < K. f = K is complete, and f > K is
  refused.
- P4. Partial topologies are removed before the donors, the seed groups and
  twins, the sample, the share, the layout and the counts. Donor ids run
  contiguously over the kept (seed key, k) keys, computed by hand.
- P5. The record checks run on the full tree before the drop.
- P6. The plan records per task partial_topos [{topo, finished, expected}]
  and n_dropped_partial (the detections of the dropped topologies). It
  records n_iters, topo_counts, positions_sha256 (independently recomputed
  with canonical JSON), shards, n_topos and empty_topos after the drop, and
  at the top level `drop_partial_topologies` true and the totals.
- P7. The printed header line, then at most ten `[plan]   <task> topo <k>:
  <f> of <K>` lines.
- P8. With false nothing of Block 10 is read, the line `[plan] partial
  topologies: not checked (drop_partial_topologies false)` is printed, and the
  JSON equals the parent commit's (created, git and free_space pinned).
- P9. With true, the raw topology folders must equal Top u E, or the plan is
  refused naming both sides. An empty bank after the drop is refused, and
  refused tasks are reported in 6.2's format.
- P10. The export drops the plan's list and refuses a listed topology that is
  absent from its tree. No row comes from a dropped topology, read equals the
  post-drop n_iters, and the gate passes.
- P11. The plan is deterministic.
